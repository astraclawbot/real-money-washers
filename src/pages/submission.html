Project overview

A static site.
Delivered at the edge.

The project combines responsive HTML pages, CSS, JavaScript, and locally hosted assets. A small Node.js build script assembles the pages and assets into a deployable dist/ directory.

The generated files are uploaded to a private Amazon S3 bucket. Amazon CloudFront provides the public entry point, caches website content, and accesses the S3 origin through Origin Access Control.

AWS services used

Storage and delivery.

Amazon S3
Stores the generated HTML pages and website assets in a private bucket in the Ohio region (us-east-2). Block Public Access is enabled.
Amazon CloudFront
Delivers the website through its public distribution domain, caches content at edge locations, and accesses the S3 origin using OAC. The default root object is index.html.

Security considerations

A private origin.

Block Public Access
All four S3 Block Public Access settings are enabled, protecting the bucket from public access through public ACLs and bucket policies.
Origin Access Control
CloudFront uses OAC to access the S3 origin. Visitors request content through the CloudFront distribution.
Distribution-scoped permission
The bucket policy grants the CloudFront service principal permission to read objects with s3:GetObject. An AWS:SourceArn condition scopes that permission to the designated distribution.

Challenges and resolutions

Getting the right page.
And the latest version.

Opening the root URL

Challenge
Opening the base CloudFront URL did not load the index.html file stored at the root of the S3 bucket.
Resolution
The CloudFront distribution’s default root object was set to index.html. The base URL then opened the website’s landing page without requiring the filename in the address.

Showing updated files

Challenge
After uploading updated website files to S3, CloudFront could continue serving cached copies of the previous version.
Resolution
Create a CloudFront invalidation for /* to clear cached pages and assets, then wait for its status to become Completed before checking the website. Refresh the browser or use a private window if its local cache still shows the previous version.

Lessons learned

Configure the entry point.
Refresh the cache.

Default root object
CloudFront needs a default root object to serve the landing page when visitors open the base distribution URL. Setting it to index.html allowed the homepage to load without specifying the filename in the URL.
Cache invalidation
Uploading updated files to S3 does not immediately replace copies already cached by CloudFront. Creating an invalidation for /* clears cached pages and assets so CloudFront can fetch the latest files from S3 on subsequent requests. Wait for the invalidation to complete before checking the update; the browser may also need a refresh or a private window to avoid its own cached copies.
